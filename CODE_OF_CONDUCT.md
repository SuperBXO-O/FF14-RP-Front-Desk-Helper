# Code of conduct

## Expected behavior

- Discuss problems using reproducible evidence and focused examples.
- Respect differing experience levels, languages and deployment environments.
- Search existing discussions before opening a new Issue.
- Accept that maintainers may decline, defer or remove work outside the project's scope.
- Protect privacy by removing player names, customer records, tokens and other sensitive data.

## Unacceptable behavior

- Harassment, discrimination, threats, doxxing or personal attacks.
- Spam, repeated duplicate requests, mass mentions or deliberately disruptive reports.
- Pressuring maintainers for private customization, guaranteed delivery dates or unpaid support.
- Publishing another person's private data or disclosing an unresolved vulnerability.
- Using issues to impersonate maintainers or misrepresent an unofficial deployment as official.

## Moderation

Maintainers may edit or remove content, close or lock discussions, and restrict participation when behavior harms the project. Enforcement aims to protect contributors and keep technical discussion actionable.

Use GitHub's report and block tools for immediate harassment, and contact the repository owner through their GitHub profile for other conduct concerns. Security vulnerabilities follow the private process in `SECURITY.md`; do not use a public issue for either category.
